# Launcher 应用开发规则

本文档记录新增 T-Display K230 launcher 应用时需要遵守的规则。

## 硬件组合

除非应用本身就是 K230 主控的核心功能，否则 launcher 中的外设都应按可选硬件处理。

| 组合 | 硬件 |
| --- | --- |
| 主板 | K230、AHT20、摄像头、以太网、HDMI |
| nRF52840 板 | nRF52840 BLE 桥、外部 I2S 功放 |
| nRF9151 键盘板 | nRF9151、TCA8418/TCA8414 键盘、BQ27220、BQ25896、键盘背光 |

## 可选外设规则

如果应用依赖可选外设，必须先探测外设是否存在。外设不存在时，只跳过相关功能，
不能影响应用的其他核心流程。

示例：

- 电池电量、电流、电压依赖 `BQ27220`。只有检测到电量计或有效的内核电池
  power-supply 节点时，才允许显示或发布有效电池遥测。
- 充电输入状态和充电电流控制依赖 `BQ25896`。未检测到充电芯片时，需要隐藏或禁用
  充电相关操作。
- 硬件键盘和键盘背光依赖键盘底板。未检测到键盘时，必须保留软键盘输入能力。
- nRF9151 LTE/GNSS 功能必须先验证 modem UART 和 AT 响应。Meshtastic 位置功能
  在 nRF9151 不存在时必须跳过 GNSS 发布。
- 需要 nRF9151 SIM/LTE/GNSS 状态的应用应读取统一 nRF9151 manager 状态，
  不要直接各自打开 AT UART。
- AHT20 温湿度只有在读取成功时才发布。

## UI 行为

- 可选硬件不可用时，应显示“不可用/未检测到”，不能直接当成应用崩溃。
- 不能因为某一个可选传感器缺失而阻塞应用主要功能。
- 用户设置应在硬件动作或参数校验成功后再持久化。
- 控件密集页面需要分别设计横屏和竖屏布局，不能只依赖自动缩放。
